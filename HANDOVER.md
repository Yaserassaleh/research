## 3. Finish the people pass (X41–X47)

### 3.1 Procedure (what was done for X01–X40)
1. Read research/people_pass/pass_state.json (tracker). Confirm `git status` is clean apart from files you expect.
2. Launch one background research agent per batch with the prompt in §3.2 (model: a lighter model such as Sonnet is
   enough for these small institutions). Max 4 concurrent: the account's 5-hour usage window was exhausted twice with
   6 concurrent agents and once with 16, killing the running agents each time. A batch takes 40–90 minutes.
3. When an agent reports done (or its note research/people_pass/<BATCH>.md appears), validate its files:
   `python3 tools/build_db.py --out <scratch dir> --only <id1>,<id2>` must report invalid_json 0,
   broken_source_refs 0, vocabulary_errors 0. Then commit the institution files plus the note
   ("People pass Xnn: <institutions> executives verified"), push with `git push -u origin claude/tender-volta-xqmo8b`,
   update the tracker, launch the next batch. Commit only finished batches; never commit a file an agent is still
   editing.
4. If a run is interrupted (usage limit): `git status`; for each modified institution file run the validation above;
   keep valid files and relaunch the batch with this sentence added after the first paragraph of the prompt:
   "NOTE: a previous run of this batch was interrupted. research/institutions/<files> already contain valid partial
   edits from it (new sources, updated people). Do not discard them: read each file, verify what is there against the
   sources cited, and complete whatever is missing or unverified." Revert invalid files with `git checkout -- <file>`.
   If every person in a file carries today's `checked` date and the file validates, the batch is complete and only
   the note is missing (write it centrally from the diff, as for X36 and X40).

## 4. LinkedIn pass — decision needed, then run or replace

Facts: LinkedIn pages answer HTTP 999 to automated reads and must never be opened by logging in; WebSearch declines
name-based look-ups of individuals (the agents do not work around this). L01 and L02 therefore used institution +
role queries restricted to linkedin.com and matched results to the roster by name, employer and function
(PEOPLE_DEEP_DIVE.md §7). Yield: 7 verified URLs from 149 searches across the 12 highest-scoring institutions.
Main-pass agents also record LinkedIn links printed on official pages and matches that appear in ordinary searches,
which is where most of the 43 new verified URLs came from.

Decision taken by the user on 13 Oct: the manual review worklist (option 1 below). The automated L batches are not
run unless the user asks again.

1. Manual review worklist — DONE, 13 Oct 2026: `python3 tools/linkedin_worklist.py build` writes
   `exports/linkedin_review_worklist.xlsx` (sheets: Read me with the rules, Decision-makers, Board and others) and
   a CSV copy. 639 decision-makers and 409 board/other members across all 96 institutions have no verified URL;
   rows are in ARTA-score order with chief executives and chairs first, and carry title, functions, appointment,
   education, career, unverified LinkedIn leads the agents saw, the institution's LinkedIn page and a suggested
   search string. The reviewer fills the yellow columns (URL, Confirmed / Not found / Ambiguous, reviewer, date,
   notes). Then `python3 tools/linkedin_worklist.py apply exports/linkedin_review_worklist.xlsx` writes confirmed
   URLs into the institution files (status "Verified (profile/search match)", tier-4 source "LinkedIn profile
   (manual review)"), turns Not found into "Not verified", puts Ambiguous notes into open_items, logs everything in
   research/central_edits.json, and keeps each file's formatting; rebuild afterwards. Re-run `build` after X41–X47
   so the list covers their people too (the reviewer's answers in the old file must be applied first).
2. Not chosen: run L03–L16 as planned (research/people_pass/linkedin_plan.json; prompt in PEOPLE_DEEP_DIVE.md §7;

## 7. Environment facts (cloud session) that cost time to learn

- Network access must be "Full" in the environment settings. Even then the built-in WebFetch tool fails (ENOTFOUND);
  `python3 -E tools/pdftext.py "<url>"` and `curl -sSL` work through the session proxy (CA bundle
  /root/.ccr/ca-bundle.crt; set SSL_CERT_FILE to it if a Python TLS call fails).

  ran out mid-batch twice; agents then recorded "not checked" rather than guessing). LinkedIn answers 999.
